# pr-watch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `github pr-watch` subcommand — a foreground blocking watcher that live-displays a PR's CI/review/merge state and exits with a meaningful code when the PR reaches a terminal state.

**Architecture:** Single Python script `scripts/pr_watch.py` wired into `run.sh`. Shells out to `gh` (no new deps), one `gh pr view --json` call per poll cycle, in-place redraw of a compact status block, terminal-state exit logic per the spec.

**Tech Stack:** Python 3 (stdlib only), `gh` CLI, bash (`run.sh` dispatcher).

**Spec:** `docs/superpowers/specs/2026-10-09-pr-watch-design.md`

## Global Constraints

- No new third-party dependencies. Stdlib Python + `gh` subprocess only.
- Follow the repo's existing script pattern: `scripts/<name>.py` executed via a `run.sh` `case` arm.
- `gh` must be authenticated; fail fast with a pointer if not (spec §7).
- Default poll interval **15s**; subcommand name **`pr-watch`**; script **`scripts/pr_watch.py`**.
- Exit codes: `0` merged/approved, `1` closed-unmerged, `2` CI-fail, `3` no-PR, `130` Ctrl-C (spec §5).
- One `gh pr view --json` fetch per cycle must request exactly these fields: `state,mergedAt,reviewDecision,latestReviews,statusCheckRollup,headRefName,title,url,number`.
- Commit messages need a `+semver:patch|minor|major` token and subject ≤75 chars (repo hook).

## Review Focus

The spec is silent on these inputs; each is pinned to the owning task with a test/verification:

1. **PR with zero checks** — `statusCheckRollup` empty. Must not trigger the CI-fail branch (nothing to fail); CI line shows `0 checks`. Pinned in Task 3.
2. **Pending/queued checks** — a check still running must never count as "settled", so CI-fail only fires when every check is terminal. Pinned in Task 3.
3. **`reviewDecision` empty string** (no reviews yet / review not required) — must render as "review required", not crash. Pinned in Task 4.
4. **Ctrl-C mid-sleep / mid-fetch** — must exit 130 cleanly with no traceback. Pinned in Task 5.
5. **`gh` transient network failure** (Zscaler reset) — retry up to 3× with backoff before giving up, not crash on first failure. Pinned in Task 2.

### Task 2: `classify_checks` — zero-check and pending handling

**Files:**
- Modify: `scripts/pr_watch.py`

**Interfaces:**
- Consumes: nothing external; operates on the `statusCheckRollup` list from `fetch_state`.
- Produces: `classify_checks(rollup: list[dict]) -> CheckSummary` where `CheckSummary` is a dataclass with `passed: int`, `pending: int`, `failed: int`, `failed_names: list[str]`, and `settled: bool` (`settled is True` iff `pending == 0`). Each rollup entry has a `status`/`conclusion` (GitHub check-run shape) or `state` (status-context shape); treat both.

- [ ] **Step 1: Write the classification rules as a docstring + skeleton**

`classify_checks` normalizes two GitHub shapes: check-runs (`status`: `QUEUED/IN_PROGRESS/COMPLETED`, `conclusion`: `SUCCESS/FAILURE/…`) and status-contexts (`state`: `PENDING/SUCCESS/FAILURE/ERROR`). A check is **pending** if not yet completed, **failed** if conclusion/state is `FAILURE`/`ERROR`/`TIMED_OUT`/`ACTION_REQUIRED`/`CANCELLED`, else **passed**. Empty `rollup` → all zeros, `settled=True`.

- [ ] **Step 2: Implement `classify_checks` + `CheckSummary`**

Per the rules above. `failed_names` collects each failing check's `name` or `context`.

- [ ] **Step 3: Verify zero-check and pending cases (Review Focus #1, #2)**

Run inline:
```python
import scripts.pr_watch as w
assert w.classify_checks([]).settled is True and w.classify_checks([]).failed == 0   # zero checks
s = w.classify_checks([{"status":"IN_PROGRESS","name":"build"}])
assert s.pending == 1 and s.settled is False                                          # pending not settled
f = w.classify_checks([{"status":"COMPLETED","conclusion":"FAILURE","name":"test"}])
assert f.failed == 1 and f.failed_names == ["test"] and f.settled is True             # terminal fail
```
Expected: all three assertions pass.

### Task 3: `terminal_state` — the exit-code decision

**Files:**
- Modify: `scripts/pr_watch.py`

**Interfaces:**
- Consumes: the `fetch_state` dict and `CheckSummary` from `classify_checks`.
- Produces: `terminal_state(state: dict, checks: CheckSummary, exit_on_approved: bool) -> tuple[int, str] | None` — returns `None` to keep watching, else `(exit_code, message)` per spec §5 order: merged→0, closed-unmerged→1, `checks.settled and checks.failed>0`→2, `exit_on_approved and reviewDecision=="APPROVED"`→0. Zero-check PR (`failed==0`) never returns 2.

- [ ] **Step 1: Implement `terminal_state`**

Evaluate the four conditions in spec order; first match wins. Messages: merged `"✅ Merged"`, closed `"⊘ Closed without merge"`, CI-fail `"❌ CI failing: " + ", ".join(checks.failed_names)`, approved `"✅ Approved"`.

- [ ] **Step 2: Verify the decision table incl zero-check (Review Focus #1)**

```python
import scripts.pr_watch as w
mk = lambda **kw: {"mergedAt":None,"state":"OPEN","reviewDecision":"", **kw}
Z = w.classify_checks([])   # zero checks, settled
F = w.CheckSummary(1,0,1,["test"],True)
assert w.terminal_state(mk(mergedAt="2026-01-01"), Z, False) == (0, "✅ Merged")
assert w.terminal_state(mk(state="CLOSED"), Z, False)[0] == 1
assert w.terminal_state(mk(), F, False)[0] == 2               # settled + failed
assert w.terminal_state(mk(), Z, False) is None               # zero checks → keep watching
assert w.terminal_state(mk(reviewDecision="APPROVED"), Z, True)[0] == 0
assert w.terminal_state(mk(reviewDecision="APPROVED"), Z, False) is None  # flag off
```
Expected: all assertions pass.


### Task 5: `resolve_pr`, main loop, Ctrl-C, CLI flags

**Files:**
- Modify: `scripts/pr_watch.py`

**Interfaces:**
- Produces:
  - `resolve_pr(arg: str | None) -> int` — `int(arg)` if given, else parse `gh pr view --json number` on the current branch; on no PR print a message and `sys.exit(3)`.
  - `main(argv) -> int` — argparse for `[pr] --interval 15 --diagnose --exit-on-approved --once --json`; the poll loop; KeyboardInterrupt → `return 130`.
  - `diagnose_failure(state: dict) -> str` — runs `ci-debug analyze <Org/repo> --branch <headRefName>`; returns its one-line summary, or `""` with a stderr warning if `ci-debug` is missing.

- [ ] **Step 1: Implement `resolve_pr` + argparse in `main`**

`--interval` default 15, flags as in spec §3. `--once` runs a single fetch+render+terminal-check then exits.

- [ ] **Step 2: Implement the poll loop**

`while True`: `state = fetch_state(pr)` → `checks = classify_checks(state["statusCheckRollup"])` → print `render(...)` (clear screen first unless `--once`/`--json`: `print("\033[2J\033[H", end="")`) → `t = terminal_state(state, checks, args.exit_on_approved)`; if `t` is not None: print message, if `t[0]==2 and args.diagnose` print `diagnose_failure(state)`, `return t[0]`. Else `time.sleep(args.interval)`.

- [ ] **Step 3: Wrap the loop in KeyboardInterrupt → 130 (Review Focus #4)**

`try: <loop> except KeyboardInterrupt: return 130`. No traceback.

- [ ] **Step 4: Implement `diagnose_failure`**

`shutil.which("ci-debug")` → if None, warn to stderr and return `""`. Else `subprocess.run(["ci-debug","analyze",repo,"--branch",branch])`, return its trimmed stdout (first line).

- [ ] **Step 5: Live-verify `--once` and Ctrl-C (Review Focus #4, #5)**

Run against a real open PR: `python3 scripts/pr_watch.py <PR> --once` → prints one block, exits non-error. Then `python3 scripts/pr_watch.py <PR> --interval 5`, let it redraw once, press Ctrl-C.
Expected: `--once` prints the status block; Ctrl-C exits with code 130, no traceback (`echo $?` → `130`).

```bash
git commit -m "feat(pr-watch): main loop, CLI flags, ctrl-C handling +semver:patch"
```
